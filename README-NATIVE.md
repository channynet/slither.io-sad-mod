# Slither Native + NTL 시험판

Windows용 Vlither 2.6 기반 개인 사용 시험판입니다. 게임 화면과 조작은 네이티브 Vulkan 클라이언트에서 처리하며 NTL 팀 통신은 별도 작업 스레드에서 처리합니다.

## 실행

`dist/SlitherNative.exe`를 실행합니다. `app` 폴더가 실행 파일 옆에 있어야 합니다. 실행 파일만 따로 옮기지 마세요.

1. 가운데 메뉴에서 닉네임과 게임 서버의 `IP:포트`를 입력합니다. 기존 NTL에서 사용하는 서버 주소를 그대로 사용할 수 있습니다.
2. **F8**로 왼쪽 아래 팀 채팅을 열고 **설정**에서 인증키와 팀 ID를 입력합니다. **팀키 저장**을 누르면 연결하지 않고도 두 키를 현재 Windows 계정으로 암호화해 보관합니다. **팀 연결**을 누를 때도 자동 저장합니다. 다음 실행에는 자동으로 불러오므로 **팀 연결**만 누르면 됩니다.
3. **NTL 연결 확인**은 서버 응답에 자신의 접속이 포함됐다는 뜻입니다. 단순히 응답이 왔다는 것과 구분합니다.
4. **Play**로 입장하면 자신의 게임 좌표와 점수가 약 4초 간격으로 팀 서버에 전달됩니다. 죽거나 메뉴로 돌아오면 메뉴 상태로 전환됩니다.
5. 채팅은 아래 입력란에서 Enter 또는 **전송**으로 보냅니다. 실제 전송은 다음 팀 갱신 때 이뤄집니다.

팀 창은 **H 두 번** 또는 **F8**로 숨기거나 다시 열 수 있습니다. **F11**은 전체 화면입니다. 기본 게임 조작은 마우스 방향 이동, 왼쪽 클릭·Space·Shift·위쪽 화살표 가속, 휠 확대/축소입니다. 채팅 입력 중에는 게임 단축키와 가속 입력을 막습니다.

## 타겟과 사망 장면 정지 (0.11)

- **Backspace 두 번** 또는 게임 중 팀 채팅의 **설정 → 타겟 선택**으로 화면 안 상대 머리 위에 선택 문자를 표시합니다. 해당 **0~9 / A~Z**를 누르면 상대에게 빨강·흰색 과녁이 붙습니다. 선택 중 **Esc**는 취소, **Delete**는 표적 해제이며 같은 상대를 다시 선택해도 해제됩니다. 선택 문자는 선택 창을 여는 동안 고정되어 상대가 움직이거나 추가되어도 다른 상대와 바뀌지 않습니다.
- 이 버전의 타겟은 내 화면에 표시하는 기능입니다. NTL 팀의 TMS 공유 송수신이나 봇 추적은 추가하지 않았습니다. 최신 팀 정보로 확인할 수 있는 팀원과 자신은 선택 대상에서 제외합니다. 상대가 클라이언트의 수신 범위를 벗어나거나 죽으면 표적을 해제합니다. 재접속 시에도 해제하며 같은 서버 ID가 다른 지렁이에 재사용되어도 이어 붙이지 않습니다.
- **사망 순간 화면 정지**는 기본으로 켜집니다. 서버에서 내 사망을 알리면 마지막으로 그린 게임 장면을 그대로 유지합니다. 기존 자동 재시작보다 우선하며 **R / 다시 시작**으로 같은 서버 재입장, **Esc / 메뉴로**로 빠져나옵니다. 설정 창 또는 **Ctrl+F4**로 켜고 끌 수 있으며 재실행해도 설정이 유지됩니다.
- 이 화면은 클라이언트의 마지막 게임 장면이며 서버의 정확한 충돌 좌표·판정을 재현하는 리플레이는 아닙니다. 별도 녹화·매 프레임 이미지 복사 없이 기존 그래픽 메모리의 화면 한 장을 유지합니다. 정지 중 창 크기가 바뀌어도 원래 화면 비율을 유지합니다.

## 팀 채팅과 기존 미니맵 통합 (0.9)

- 왼쪽 아래 반투명 채팅 창에 수신 시각·닉네임·본문을 표시합니다. **Enter**로 입력하고 Enter 또는 전송 버튼으로 전송합니다. **Esc**는 입력을 끝내고 게임으로 돌아갑니다. 위로 스크롤해 과거 메시지를 읽는 중에는 새 메시지가 와도 맨 아래로 이동하지 않습니다.
- **설정**에서 팀 연결·저장 키 관리·이미지 태그·cosmetic·성능 옵션을 조절합니다. 채팅 창에는 별도 팀 지도를 표시하지 않습니다.
- 같은 서버의 팀원은 오른쪽 아래 기존 미니맵에 초록 점, SOS는 빨간 점과 테두리로 표시합니다. 마우스를 올리면 이름·점수·마지막 응답 경과 시간을 볼 수 있습니다. 자신의 기존 위치 표시를 중복하지 않습니다.
- 미니맵 좌표는 현재 경기장 중심과 반경, 지도 크기와 내부 여백을 반영합니다. 다른 서버·메뉴 상태·잘못된 좌표·경기장 밖 위치·10초 넘게 갱신되지 않은 응답은 숨깁니다. 서버를 바꾸면 새 서버에서 받은 응답이 확인될 때까지 이전 팀 위치를 표시하지 않습니다.
- 채팅 숨김과 **V V**의 통계 숨김은 독립적이며 팀 위치는 기존 지도에 유지됩니다. 숨긴 통계를 채팅 Enter 입력 때문에 다시 켜지 않습니다.
- 팀 통신의 정상 갱신 주기는 기존 약 4초입니다. 점은 마지막 수신 위치이며 실시간 이동을 보장하지 않습니다. 추가 서버 요청이나 게임 지도 텍스처 업로드 없이 점만 덧그립니다.
- **오프라인 화면 시험**은 실제 메시지를 보내지 않고 시험 채팅과 초록/SOS 위치를 확인합니다. 지도 시험 위치는 활성화 시점의 경기장 기준이므로 게임 접속 후 시험을 켭니다.

## 최근 서버 주소 (0.8)

주소 입력칸 오른쪽 화살표에서 최근 서버 주소를 선택합니다. **Play**로 접속을 시도한 유효한 `IPv4:포트` 주소를 최근 순서로 16개까지 기억하며, 같은 주소는 중복하지 않고 앞으로 옮깁니다. 목록 선택만으로 접속하지 않으며 **Play**를 눌러야 합니다. 처음 업데이트할 때 기존에 저장돼 있던 마지막 주소를 가져오고, 이후 목록은 `server-history.txt`에 보관해 재실행 후에도 유지합니다. 과거에 저장되지 않은 전체 방문 기록을 복원하는 기능은 아닙니다.

주소가 바뀌어 목록 순서가 달라질 때만 저장하며, 동일 서버 자동 재접속이나 게임 프레임마다 기록하지 않습니다. 잘못된 형식은 목록에 넣지 않으며 저장에 실패하면 메뉴에 알립니다. 팀키 저장과는 별개입니다.

## 복잡한 봇 기능과 일반 플레이 성능

현재 호출 경로는 `game_loop → oef → [봇 켜짐 && 내 지렁이 플레이 중] → sbot_go`입니다. 봇을 끄면 충돌점 수집/정렬, 먹이 탐색, 감기 경로 계산은 호출되지 않습니다. 입력 전송도 봇이 켜졌을 때만 봇 방향·가속 결과를 사용합니다. 시작할 때 고정 크기 봇 상태를 한 번 초기화하며, 현재 봇 전용 작업 스레드나 별도 타이머는 없습니다.

따라서 새 기능의 계산을 이 활성 조건 안에만 넣으면 일반 플레이 중 그 계산 비용이 추가되지는 않습니다. 반대로 꺼진 상태에서도 매 프레임 주변 상황을 미리 분석하거나, 백그라운드 계산을 계속하거나, 큰 모델/캐시를 항상 유지하면 CPU·GPU·메모리 경쟁으로 일반 플레이도 영향을 받을 수 있습니다.

현재 봇 계산은 화면 처리와 같은 스레드에서 실행됩니다. 켠 상태에서 계산이 길어지면 프레임과 입력 처리가 밀릴 수 있으므로, 복잡한 기능은 활성화 시 필요한 자원만 준비하고, 꺼지면 작업을 중단하며, 계산 빈도/대상 수/시간 예산을 제한해야 합니다. 무거운 계산을 별도 작업으로 분리할 때도 게임 스레드가 결과를 기다리지 않게 하고, 비활성 상태에서는 작업을 멈춰야 합니다. 아직 요청되지 않은 복잡한 봇 기능이나 실행 구조 변경은 추가하지 않았으며, 미래 기능의 영향은 실제 구현 후 봇 꺼짐/켜짐을 각각 측정해야 합니다.

## 단축키 (0.4)

NTL 9.68의 기본 키를 기준으로 이미 구현된 기능만 연결했습니다. **두 번**은 다른 키를 사이에 누르지 않고 1초 안에 같은 키를 두 번 누르는 방식입니다. 키를 누른 채로 유지해도 두 번 누른 것으로 처리하지 않습니다.

| 키 | 동작 |
| --- | --- |
| M / N | 확대 / 축소 |
| 0 두 번 | 빠른 재시작, 점수 1,000 미만 |
| 9 두 번 | 게임에서 나가기 |
| 1 두 번 | 지렁이 이름 표시 전환 |
| V 두 번 | 정보 표시 전환 |
| H 두 번 / F8 | 팀·채팅 창 표시 전환 |
| Enter | 채팅 입력란 선택 / 입력 중 전송 |
| R 누르고 있기 | 기존 보조 화면 모드 |
| K 두 번 | 보조 화면 모드 고정 전환; R을 눌렀다 떼면 해제 |
| T 두 번 | 기존 Vlither 봇 전환 |
| 3 두 번 | 기존 먹이 표현 2종 전환 |
| 8 두 번 | 기존 사망 후 자동 재시작 설정 전환 |
| . 두 번 | 설정 열기·닫기; 게임은 계속 진행됨 |
| F11 | 전체 화면 전환 |
| Ctrl+F5 | 60 → 120 → 제한 없음 |
| Ctrl+F6 | 100% → 75% → 50% 게임 해상도 순환 |
| Ctrl+F7 | 가벼운 그래픽 적용 |
| Ctrl+F8 | 내 머리 위 이미지 태그 표시 전환 |
| Ctrl+F9 | 내 이미지 cosmetic 표시 전환 |
| F6 | 기존 큰 먹이만 표시 기능 |
| F9 | 단축키 안내 표시 |

NTL과 대응하는 키의 **기능 구현은 이 클라이언트의 기존 기능**입니다. NTL의 전체 봇·스킨·보조 시스템과 동일한 구현이라는 뜻은 아닙니다. 키를 배정하기 위해 SOS·자동 회전·스크린샷 같은 기능을 새로 넣지 않았습니다. 설정 화면에서 제공하는 키 재지정과 누름 방식도 저장됩니다.

## 성능 설정

0.5에서는 화면 중간이 가로로 어긋나는 화면 찢어짐을 막도록, 즉시 화면 교체(IMMEDIATE)를 사용하지 않습니다. 기본은 지원되는 장치에서 MAILBOX, 지원하지 않으면 FIFO를 선택합니다. **Strict VSync**를 켜면 FIFO를 사용합니다. 두 방식 모두 화면 찢어짐을 허용하지 않으며, **F8** 창에서 적용된 표시 방식을 확인할 수 있습니다. 화면 표시 속도는 모니터 주사율의 제한을 받습니다.

사용하지 않는 4096×3548 배경 텍스처와 밉맵(픽셀 데이터 약 73.9MiB)을 1픽셀 텍스처로 대체했습니다. 회색 격자 모습은 유지합니다. 미니맵이 숨겨지면 그리기·전송을 생략하고, 보일 때도 해당 프레임 버퍼의 내용이 바뀐 경우에만 전송합니다. 게임 장면을 완성한 뒤 화면 합성에서 읽도록 GPU 동기화를 명시했으며, 화면 크기 변경 중 이미지 획득이 실패하면 다음 프레임을 무한 대기할 수 있던 fence 초기화 순서도 수정했습니다. 창 크기 변경 콜백 안에서 즉시 렌더링하지 않고 전환이 끝난 다음 재구성하며, 별도 크기 변경 이벤트 없이도 표시 버퍼를 복구합니다. 전체 화면 전환으로 버퍼 수가 바뀌면 표시 완료 동기화 객체도 다시 만듭니다.

추가 최적화 후보는 혼잡 서버에서 지렁이 몸통과 먹이의 화면 밖 계산을 더 줄이는 것, 미니맵 보간을 변경된 영역만 처리하는 것, 프레임 제한 대기 중 CPU 사용을 줄이는 것입니다. 이 항목들은 아직 적용하지 않았으며 같은 서버·줌·해상도에서 측정한 뒤 결정해야 합니다. 게임 서버의 핑 변동은 렌더링 최적화와 별개입니다.

- 기본: **60 FPS**, 게임 해상도 **75%**, 그림자·먹이 흔들림·광원 등 추가 효과 최소화, 회색 격자 배경.
- 글자와 팀 창은 전체 해상도로 그리며, 게임 장면만 선택한 해상도로 그립니다.
- 75% 설정은 가로·세로를 각각 75%로 줄입니다. 게임 장면 픽셀 수는 100%의 약 56%입니다. 성능 향상률을 의미하지는 않습니다.
- 그래픽 설정에서 효과를 다시 켤 수 있습니다. 팀 창의 **가벼운 그래픽 적용**으로 가벼운 설정을 다시 적용합니다.
- FPS는 최근 최대 600프레임의 평균 간격에서 계산합니다. **느린 1%**는 같은 구간의 프레임 간격 99백분위 값입니다. **33ms 초과**는 그 구간의 긴 프레임 개수입니다.
- **핑**은 게임 서버 통신 지연입니다. NTL 팀 갱신 간격과는 다릅니다. 멀리 있는 서버의 핑은 렌더링 최적화로 낮출 수 없습니다. 게임 메뉴에서는 핑이 0으로 표시됩니다.

FPS 제한·게임 해상도·전체 화면·팀 창 표시 상태는 `native-settings.json`, 창 배치는 `native-layout.ini`, 일반 그래픽·닉네임·서버·스킨·단축키 설정은 `user.dat`에 저장됩니다. 설정 변경을 약 0.75초 간격으로 감지해 저장하며 정상 종료 때도 저장합니다. 재실행할 때 가벼운 그래픽 값을 덮어쓰지 않습니다. 봇 작동·누르고 있는 보조키·재시작 명령은 실행 중 상태이므로 자동으로 다시 켜지지 않습니다.

팀 인증키와 팀 ID는 Windows DPAPI로 암호화해 `%LOCALAPPDATA%\SlitherNative\team-keys.dat`에 별도 저장합니다. 자동으로 팀에 접속하지는 않습니다. 팀 창의 **저장된 팀키 삭제**로 다음 실행 시 불러오기를 해제할 수 있으며, 이미 연결된 세션은 **연결 해제**를 누를 때까지 유지됩니다.

## 내 머리 위 이미지 태그

살아 있는 내 지렁이의 머리 위에만 표시하며, 다른 사람에게 이미지를 전송하지 않습니다. 선택한 이미지는 긴 변 최대 512px로 줄여 `personal-tag.rgba`에 보관하고 표시 여부·크기·간격은 `personal-tag.json`에 저장합니다. 원본 파일을 옮겨도 다음 실행에 복원됩니다. 이미지 파일 선택은 게임 메뉴에서만 가능하며 플레이 중에는 크기·간격·표시 여부를 바꿀 수 있습니다.

0.1에서 처음 업데이트할 때만 NTL 기본 단축키와 회색 격자 배경을 적용하고 기존 닉네임·서버·스킨·나머지 그래픽 설정은 유지합니다. 이후 사용자가 바꾼 값은 그대로 불러옵니다.

## 끊김과 조작 지연 수정 (0.7)

한산한 곳에서도 끊겼다는 사용자 보고를 바탕으로 입력·통신과 화면 표시 대기의 연결을 수정했습니다. 당시의 성능 기록은 없어 그 사건의 단일 원인은 확정하지 않았습니다.

- 기존 방향/키보드/가속 전송 간격 50/150/150ms를 33/50/50ms로 줄였습니다. 이는 [NTL 공식 변경 기록](https://ntl-slither.com/slither/)의 9.55 명시 값입니다. 이후 9.58에도 타이밍 로직 수정이 기록되어 있으므로 최신 NTL과 모든 동작이 같거나 실제 반응 시간이 같다는 뜻은 아닙니다.
- 화면 획득·GPU 완료를 한 번에 오래 기다리던 부분을 1ms 단위로 반환하도록 변경했습니다. 프레임 제한 대기 중에도 짧은 간격으로 최신 마우스 입력과 게임 통신을 처리합니다. 같은 스레드에서 수행하므로 별도 스레드가 게임 상태를 동시에 수정하지 않습니다. 드라이버의 화면 제출 자체나 크기 변경 작업까지 무조건 1ms 안에 끝난다는 보장은 아닙니다.
- 한 번의 서버 수신 처리 뒤에도 데이터가 남으면 최대 8회/소프트 예산 2ms까지 추가 처리합니다. 수신 버퍼는 64KiB로 미리 준비합니다. Windows의 기존 수신 버퍼 증가 단위는 16KiB였습니다. 이는 인터넷 왕복 시간을 줄이는 기능이 아니라 클라이언트 안에서 쌓인 데이터를 빨리 처리하는 수정입니다.
- 0.6의 FIFO 최소 이미지 수 정책을 되돌려 최소+1개를 요청합니다(장치 상한 적용). [Khronos 설명](https://docs.vulkan.org/samples/latest/samples/performance/swapchain_images/README.html)처럼 2개 버퍼는 화면 표시 시점을 놓쳤을 때 프레임 속도가 크게 떨어질 수 있습니다. 실제 지연과 안정성의 균형은 장치별로 다르며 화면 찢어짐 방지 정책은 유지합니다.
- 외곽선은 몸통 내부까지 덧칠하던 작업을 생략하고 얇은 테두리 부분만 처리합니다. GPU 대기 중 들어온 단축키는 다음 그리기까지 보존합니다.
- 서버 응답을 프레임 사이에 받더라도 현재 시각을 기준으로 핑을 계산합니다.

`dist/performance.csv`에는 약 1초마다 평균/최대 프레임 시간, 33ms 초과 횟수, 화면 대기·통신·이동 계산·그리기 준비·제출·프레임 제한 시간, 수신량, 남은 수신량, 그리기 수, 표시 모드/버퍼 수, 마지막/구간 최대 핑을 기록합니다. 마지막 핑은 새 응답이 없으면 유지되며 구간 최대 핑 0은 새 측정이 없었다는 뜻입니다. 메뉴·크기 변경도 프레임 간격에 포함되므로 재현 당시 상황과 함께 해석해야 합니다. 시간 항목은 CPU에서 측정한 값이며 GPU 실행 시간이나 실제 입력부터 화면 표시까지의 지연을 직접 측정하지 않습니다.

기록 쓰기는 별도 스레드에서 수행하고, 게임 쪽은 기록 잠금을 기다리지 않습니다. 현재 기록과 이전 기록(`performance.previous.csv`) 두 파일만 유지하며, 재실행 또는 약 3,600개 기록마다 교체합니다. 팀키·채팅·닉네임·서버 주소는 기록하지 않습니다.

## 0.12 수비형 봇

- 기존 `T` 두 번으로 켜고 끕니다. 전략은 수비형 하나이며, 별도 경로/전략 UI를 그리지 않습니다. 시작 시 봇은 OFF입니다.
- 실제 이동 속도와 회전 제한으로 1.5초 앞의 17개 경로를 비교합니다. 몸통은 점 사이 선분까지 검사하고, 상대 머리가 남길 몸통과 맵 경계도 피합니다.
- 안전한 경로를 우선하며 먹이는 안전 여유가 있을 때만 고려합니다. 자동 부스트와 점수에 따른 자기 몸 돌기를 제거했습니다. 봇이 켜져 있으면 수동 부스트 입력도 사용하지 않습니다.
- 지연에 따른 조작 지연을 예측에 반영하고, 안전한 후보 사이에서는 이전 방향을 선호합니다. 예측 모델은 서버의 충돌 판정을 완전히 재현하지 않으며 상대 급회전/포위/장기 통신 지연에는 한계가 있습니다.
- 최대 약 30회/초 계산, 최대 512개 가까운 위험 보관, 고정 배열 사용. 초과 위험은 안전하지 않은 미확인 범위로 처리합니다. 전체 몸통 수집 비용은 수신된 몸통 수에 비례합니다. OFF에서는 경로 계산을 하지 않습니다.
- `performance.csv` 끝에 `bot_ms`를 추가했습니다. 프레임당 평균 봇 계산 시간이며 `update_ms`에 포함되므로 두 값을 합산하지 않습니다.
- 자동 검사: 경계, 연속 몸통, 좁은 틈, 교차 머리, 지연, 장애물 초과, 이전 방향 포기, ID/재생성, 계산 주기, OFF 무계산. 512개 장애물/200회 합성 검사 평균 약 0.60ms/판단(이 PC, 검사 빌드); 실제 생존율 개선 수치는 아직 측정하지 않았습니다.

개선 연구: 회전 가능한 경로를 비교하는 [Dynamic Window Approach](https://publications.ri.cmu.edu/the-dynamic-window-approach-to-collision-avoidance)의 원리를 참고해 이 게임의 멈출 수 없는 이동에 맞게 구현했습니다. 로봇 실험의 안전 보장을 게임에 그대로 적용하지 않습니다. 사용자가 제공한 sliterapp ZIP의 급회전 반복 사망 기록은 방향 유지 설계의 참고 자료로만 사용했으며 코드/학습 모델은 복사하지 않았습니다.
